# T3.4 Frozen-RTL benign wear baseline

Goal: generate one summary row and one windowed D$ wear heatmap for every benign workload, with caches on and no detector.

Created `analysis/wear_baseline.py` and replaced the `Makefile` wear stub. The script builds the complete 13-workload benign registry, runs each with a 2 KiB D$, 16-byte lines, 20-cycle backing memory, `DETECTOR=NONE`, and 10,000-cycle windows. It requires HALT 0 and each workload's self-check, replays the D$ access trace through the independent cache model, computes the exact Section 4 PMR and illustrative `T_fail`, and generates a summary CSV and heatmap for every workload. Each figure and the table have JSON provenance with the frozen RTL tree, generating script, source CSV hashes, and figure/table hash.

Acceptance command: `make wear` from `writehammer/`. Result: exit 0, 13/13 workloads passed, with exact golden replay on every trace. Output: `analysis/wear_baseline_f3a7ccb0eb4d.csv`, its `.json` sidecar, and 13 `analysis/wear_baseline_f3a7ccb0eb4d_*_heatmap.png` figures, each with a `.json` sidecar. Raw per-line and window CSVs plus simulation logs are in `work/wear_baseline/baseline_f3a7ccb0eb4d/`. The summary contains 13 distinct workload rows; all 13 heatmaps and sidecars exist, and the table hash matches its sidecar. PMR over all lines ranges from 1.0 to 127.93722842512231 in this baseline. The latter is crc32 and is a measured finding, not a manually adjusted result.

The source RTL tree is `f3a7ccb0eb4d137ed8139d0285d4a9600de07f0f`, as recorded in `docs/RTL_FREEZE.md`. No RTL or existing tests changed. If RTL changes after the freeze, rerun `make wear` and record the reason. This is a modeled-NVM single-core result, not a claim about SRAM endurance or multicore attack attribution. `T_fail` assumes 1e15 writes and extrapolates from these short runs.
