# T1.3 Performance counters over MMIO

- **Goal:** counters for cycles, instructions retired, stall cycles by cause (load-use, branch/jump flush), exposed by MMIO start/stop/halt writes and printed as one CSV line at halt. Accept: counters match hand-computed values on a tiny program with known stall counts.
- **Done:**
  - Core: MMIO window `0xF000_0000-0xF000_0FFF`. Stores there never reach `dmem` or the D$ (`MemStoreM`) and appear as one pulse on new top-level outputs `mmio_we/addr/wdata`. Loads from the window are unsupported (KI-005).
  - `tb/sys_monitor.sv`: HALT (+0x00), START (+0x04), STOP (+0x08), PHASE (+0x0C), PUTCHAR (+0x10); counters cycles, instret (shadow valid bits shifted with the real hold/clear controls, so freezes and bubbles are handled), load-use stall cycles, flush cycles (2 per redirect), raw `imiss`/`dmiss` cycles; one `PERF,...` CSV line at HALT with the column order in the file header.
  - `tb/tb_prog.sv` (generic program runner with a timeout that is always a failure), `tests/prog_runner.py`, `tests/perf_tests.py` (known-answer tests), `tests/mutants/perf_mutants.py` (7 mutants).
- **Window definition (tb/sys_monitor.sv):** cycles after START's Memory cycle through STOP's Memory cycle; START is counted as retired, STOP is not. Events are counted by the cycle their signal is high, so a hazard in or just before START's Memory cycle is not counted. Tests put a NOP right after START.
- **Results:** `make test`: perf 21/21 (4 window programs x caches off and caches on at LAT 1, 2, 3, 10, plus a misc test for exit code, PHASE, PUTCHAR, whole-run counting and a timeout). Hand-computed expectations: straight line 4 cycles; load-use + taken branch N=6 s=1 f=1 gives 9 cycles; two load-use N=6 s=2 gives 8; two redirects N=5 f=2 gives 9. With caches on, instret, load-use and flush counts equal the caches-off values at every latency. Mutants 27/27 caught (7 new).
- **Problems:**
  1. Counters read low and the window missed events at the start. Root cause: the hazard signal of an instruction right after START fires in START's own Memory cycle, outside the window, while its bubble lands inside. Not a counter bug; defined the boundary rule and padded the tests. My first expected values assumed events strictly inside the window and were wrong (the test caught them). Corrected values are re-derived by hand in `tests/perf_tests.py`.
  2. HALT print missed the last retired instruction: the PERF line was printed at the edge where the counters had not yet absorbed the HALT store's own cycle. Fixed by printing one cycle after the HALT store. The `misc` test (whole-run `instret` = 8) is the regression test: it failed at 7 before the fix.
  3. PUTCHAR output ran into the `HALT` line and broke parsing. PUTCHAR now prints `CHR <code>` lines.
- **Deviations:** none. Changed locked files: `tests/run_mutants.py` (CHG-004), `tests/paths.py` (CHG-005).
