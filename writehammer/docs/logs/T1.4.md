# T1.4 Software toolchain flow

- **Goal:** `crt0.S` (set `sp`, zero `.bss`, call `main`, write the exit code to the halt MMIO), a linker script (text, data, bss, stack in 256 KB), and a script that builds an ELF into a `$readmemh` hex. Accept: a C program that writes a checksum to the halt MMIO runs and the testbench reads it correctly.
- **Done:**
  - `sw/crt0.S`, `sw/link.ld` (256 KiB at 0; text and rodata first, `.data` on a fresh 4 KiB page, `.bss`, stack in the top 16 KiB; an `ASSERT` stops the image overlapping the stack), `sw/mmio.h`, `sw/build.py`, `sw/smoke/checksum.c`.
  - `build.py` compiles with `-march=rv32i_zicsr -mabi=ilp32` (see problem 1), converts the binary to one little-endian word per line, and rejects any build whose ELF architecture attribute is not rv32i or that contains an instruction outside the RV32I base list (checked with `objdump -M no-aliases`).
  - RTL: top parameters `MEM_WORDS` (default 256, so every earlier test is unchanged; the C flow uses 65536) and `DMEM_FROM_IMAGE`. `imem`, `dmem` and `backing_mem` take a depth and an image file; `imem` now zero-fills before loading.
  - `tests/toolchain_test.py`, `tests/image_runner.py`, `tests/mutants/toolchain_mutants.py` (3 mutants).
- **Oracle:** the same C compiled natively with the host gcc, at `-O0` and `-O2` (they agree: 1892521041, so the program has no undefined behavior). Not taken from the RTL or the RISC-V compiler.
- **Results:** `tests/toolchain_test.py` 10/10: build ok; `counter` and `table` are in `.data`, `scratch` in `.bss` (nm); the core halts with exactly 1892521041 with caches off and on at LAT 1, 2, 3, 10; a control run without loading the data image gives 1308050122 (different, so `.data` is really exercised); `build.py` rejects a `mul` program. Mutants 30/30 caught (3 new). Full `make test` result in `work/full_test.log` / the run logs.
- **Problems:**
  1. `-march=rv32i` has no matching multilib in this GCC: `-print-libgcc-file-name` returns the default multilib's `libgcc.a`, whose architecture attribute is `rv64i2p1_m2p0_...`. Linking `-lgcc` for software multiply/divide would pull an rv64 library. Root cause confirmed with `readelf -A` on both libraries. Fix: `-march=rv32i_zicsr` (the closest rv32 multilib, RV32I-only helpers) plus the ELF check in `build.py`, which would have caught it anyway.
  2. My linker script discarded `.riscv.attributes`, so the architecture check found nothing and the build failed ("architecture is unknown"). The check was right; the section is now kept.
  3. The first smoke program never wrote `table`, so GCC moved it into `.rodata` and `.data` was empty: the test would have passed with `.data` loading broken. The program now writes its initialized data, and the test asserts the symbols' sections and has the no-image control run.
  4. Icarus 12 cannot cast a string ternary in a `localparam`; used a nested `generate` instead.
  5. A first manual check of the no-image control showed no `p.vvp`: `iverilog ... | head -3` killed the compiler with SIGPIPE. Not a design problem; rerun without `head`.
- **Deviations:** libgcc contains one `csrr ... vlenb` in an unrelated object; it is not linked into any image here, and `build.py`'s per-instruction check would fail the build if it ever were.
- **Open items:** the unified 256 KB memory with an arbiter is T2.1; until then both memories hold the full image (KI-007).
