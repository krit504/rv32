# T2.7 Cache counters and the size / line-size sweeps

- **Goal:** counters for I$/D$ accesses, hits, misses, fills, dirty write-backs and miss-stall cycles, merged into the stall breakdown; cache-size and line-size sweeps for miss rate. Accept: miss rate vs size plot per benchmark, regenerated by `make caches`.
- **Done:**
  - Counters in the RTL (`icache.sv`, `dcache.sv`, top-level outputs `ic_cnt_*`, `dc_cnt_*`): I$ lookups, misses, stall cycles; D$ accesses, hits, misses, fills, write-backs, bypasses, refills after bypass, stall cycles, stores. `tb/tb_prog.sv` snapshots them at the program's MMIO START and STOP so they are measured over the same window as the cycles and instruction counts, printed as `CACHEWIN` at HALT. The stall breakdown columns are load-use, flush (2 per redirect), I$ miss and D$ miss cycles (`tb/sys_monitor.sv`); imiss and dmiss cycles can overlap other stalls and each other, so the columns do not add up to cycles minus instructions.
  - `analysis/caches.py` (`make caches`): all 13 workloads x six geometries (size sweep 1, 2, 4, 8 KiB with 16-byte lines; line-size sweep 16, 32, 64 bytes at 2 KiB), memory latency 20, Verilator, every run must exit 0 (the workload's own self-check) or the script stops. Writes `analysis/caches.csv` (78 rows), `analysis/caches_size.png`, `analysis/caches_line.png`, each figure with a provenance sidecar `.json` (script, git commit, CSV sha256 `9f28bd10e1fa115c...`).
  - Definitions: `d_miss_rate` = D$ misses / D$ accesses; `i_miss_rate` = I$ misses per retired instruction (the I$ is looked up every cycle, including repeated lookups of one address while the pipeline is stalled, so per-instruction is the stable denominator).
- **Results (from `analysis/caches.csv`, 1 KiB -> 8 KiB, 16-byte lines):**

| CoreMark | 0.73% -> 0.00% | 0.0042 -> 0.0001 | 1.5457 -> 1.4341 |
| nettle-aes | 58.40% -> 6.23% | 0.0152 -> 0.0000 | 3.7543 -> 1.33 |
| nettle-sha256 | 4.71% -> 4.71% | 0.2227 -> 0.0000 | 6.1318 -> 1.2421 |

  Line size at 2 KiB (16 / 32 / 64 bytes):

| Workload | D$ miss rate | I$ misses / instr |
|---|---|---|
| Dhrystone | 3.06% / 3.06% / 3.06% | 0.0979 / 0.0559 / 0.0373 |
| nettle-sha256 | 4.71% / 2.86% / 3.36% | 0.2149 / 0.1097 / 0.0561 |

| storeloop | 25.00% / 12.50% / 6.25% | 0.0000 / 0.0000 / 0.0000 |

  What the numbers say: streaming workloads (`memcpy_big`, `memset_big`, `storeloop`: 16 KiB buffers, larger than every cache here) are insensitive to cache size and their miss rate falls in proportion to the line size (storeloop 25%, 12.5%, 6.25% = one miss per 4, 8, 16 words); Dhrystone's ~6.4 KB of code thrashes I$s of 4 KiB and below and fits in 8 KiB (CPI 5.69 -> 1.46); `nettle-aes` is the most cache-size sensitive data workload.
