# T4.1 Deterministic LFSR and attack harness

Goal: provide a seed-parameterized deterministic LFSR and prove a known-answer sequence. The RLA/RTA/RnLA/RnTA taxonomy is prior work of the author's group (TENDRA and the Write Hammer draft); this task does not define the four attack behaviors.

Created `sw/attacks/lfsr.h` (32-bit Galois transition, reflected tap mask `0x80200003`), `sw/attacks/lfsr_known.c`, and `tests/attack_lfsr.py`. Seed zero is normalized to one because the zero state otherwise remains zero; the caller supplies all other seeds unchanged. The library makes no claim of maximal period. A volatile test seed prevents the compiler from folding the tested sequence away. Literal expected states are derived from the transition polynomial. The test builds the source natively and through `sw/build.py`, which rejects non-RV32I instructions, and runs the latter on the cached core at memory latency 20. A changed tap (`0x80200001`) is compiled and run in both environments and must cause a nonzero self-check exit. This is a real behavior-changing control, not an equivalent mutant.

Acceptance command: `scripts/run.sh -- python3 tests/attack_lfsr.py`. Result: 4/4 checks passed: native known answer, RV32I known answer, native broken-tap control exits 2, RV32I broken-tap control exits 2. Raw run output is under `work/attack_lfsr/`. `scripts/run.sh -- scripts/check_locks.sh --add` locked the two new tests; `scripts/run.sh -- scripts/check_locks.sh` reports 51 protected files OK.

Preparatory harness added in the same task commit: `tests/attacks.py` loads and validates an author-supplied `sw/attacks/manifest.json`, including all four kinds, both forms, the specified 2M-cycle attack target and seeds 1–5 for randomized kinds. `analysis/attack_runner.py` will build each C program with cache geometry and attack parameters as `-D` flags, require a native self-check, run the RV32I image, replay its D$ trace and calculate wear statistics. It takes cache and line sizes for the direct-form geometry sweep. `analysis/attack_validate.py` will compare each attack PMR with every benign workload and generate the validation table and heatmaps with source hashes. These scripts compile and their CLI help works; they have not been run on attack programs because no attack definition or source exists yet. Visual wandering still requires inspection of the generated randomized heatmaps.
