# T6.2 — CSV-driven figures and tables (Phase A)

`analysis/plots.py` reads only committed CSV data. Section 7's `results.csv` schema has aggregate wear but no per-line/window counts, whereas Section 8 requires per-line heatmaps. `analysis/eval_wear_export.py` therefore normalizes each completed run's measured wear-window CSV into `analysis/eval_wear_windows.csv`; `plots.py` reads that CSV alongside `results.csv`. The normalized CSV and every generated figure/table have script, commit and source-hash provenance sidecars. The attacks in these outputs are prior work of the author's group (TENDRA and the Write Hammer draft).

Commands:

```sh
scripts/run.sh -- python3 analysis/eval_wear_export.py
make plots
```

Phase A result: four cached development runs contributed 292,864 line/window rows. `make plots` regenerated the measured miss-rate-vs-size points, CPI/stall figure, four per-line heatmaps and two tables (PMR/T_fail; false-positive/detection fields) from CSVs only. Empty false-positive/detection cells remain empty because T5 has not supplied those measurements. The figures are explicitly labelled as measured development data. No detector or physical-cost numbers were invented.

**Status: PARTIAL.** Section 8 also requires detector comparisons and controls, a sensitivity plot, area/Fmax and hypotheses. Those figures/tables cannot be completed from the six-row development CSV. The final plot command is wired, and it will regenerate available plots from scratch after the full matrix and supplementary wear CSV exist.
