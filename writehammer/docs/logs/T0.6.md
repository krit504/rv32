# T0.6 Lock-in

- **Goal:** `docs/CRITERIA.md` (verbatim Section 1, 3, 4, calibration and held-out lists, T4.7 rule, mutant lists); `docs/LOCKED.sha256` over it plus `tests/`; `scripts/check_locks.sh` run by `make test`.
- **Done:**
  - `scripts/make_criteria.py` extracts the sections from the spec by pattern, so the text is verbatim, and records the spec's sha256 in the header. Mutant lists: T1.2, T1.6, T3.5, T5.7, T5.10 task lines. The calibration and held-out lists are inside Section 3.
  - `docs/LOCKED.sha256`: 14 files (`docs/CRITERIA.md`, the spec itself, every file under `tests/`). The spec is locked too, because Section 6's acceptance checks are protected and live only there.
  - `scripts/check_locks.sh`: a changed or missing locked file fails unless one `## CHG-` entry in `docs/CHANGE_LOG.md` names the path and its current sha256 (or `DELETED`). `--add` appends new protected files and never rewrites a line. Unlocked protected files are reported.
  - `make test` now runs `make locks` first; `make locks-selftest` runs `scripts/selftest_locks.sh`.
- **Commands and results:** `make locks`: `[locks] OK: 14 locked file(s) verified`. `make locks-selftest` on a throwaway copy: clean passes; edited locked file fails; an entry split across two CHG blocks fails; one proper entry passes; deleted locked file fails.
- **Acceptance:** passes on a clean tree and fails after a deliberate edit without a CHANGE_LOG entry. Pass.
- **Problems:** the first version accepted a path and a hash appearing in two different entries. Tightened to a single-entry match; the self-test has a case for it.
- **Deviations:** none.
- **Open items:** files added to `tests/` by later tasks must be locked with `scripts/check_locks.sh --add` when the task finishes; the T7.8 audit checks that no protected file is left unlocked.
