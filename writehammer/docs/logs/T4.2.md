# T4.2 — Recurring Location Attack

The attack names and behaviors are prior work of the author's group, not a new taxonomy here. The local papers are `TENDRA_Targeted_Endurance_Attack_on_STT-RAM_LLC.pdf` (Recurring Location and Recurring Toggle Attack) and `Write_Hammer (1).pdf` (Section III.B, all four attacks), in `/home/kritin/Documents/Research papers/`. In those papers, **L** means recurring updates of a fixed location or fixed array; **T** means toggling between two target locations with variable switching time. **Rn** selects targets at random: RnLA moves a single target, and RnTA selects and toggles within changing pairs. The paper's LLC/L2 mechanism is translated to this project's D$: a paper-form target array exceeds the D$ and forces dirty evictions; a direct form targets one or more lines at the configured D$ geometry.

`sw/attacks/attack_core.h` contains the shared parameterized kernel. The four small C entry files and full registry were introduced together so the locked registry and runner can load all eight variant names. Only RLA is accepted in this task; later task logs record each other attack's own acceptance. `ATTACK_RUN_CYCLES` controls a calibrated operation count; it never changes the result by timing. The RLA direct form has one chosen line, while the paper form sweeps a 2064-byte array at the primary geometry. The self-check sums target values and checks each swept word. No MMIO read contributes to a result.

Acceptance commands, run from this worktree:

```sh
scripts/run.sh -- .venv/bin/python tests/attack_program.py --kind RLA
scripts/run.sh -- .venv/bin/python analysis/attack_runner.py --case rla_direct_s1 --case rla_paper_s1
scripts/check_locks.sh
```

Result: native GCC and RV32I caches-off/on HALT 0 for both forms; the C5 stale-store core mutant returns 127 in both forms. Golden cache replay matches exactly. Measured windows are 2,000,046 and 2,035,280 cycles. PMR(all) is 128.0 direct and 2.4707615 paper, generated by `analysis/attack_runner.py` and `analysis/wear_stats.py` with source-hash sidecars under `work/attack_run/`.

The paper form's broad write distribution cannot beat the benign `crc32` PMR(all) 127.937; T4.7's strict rule will fail for this authentic paper behavior. This is recorded now rather than changing the attack to satisfy a detector comparison. No detector work is done here.
