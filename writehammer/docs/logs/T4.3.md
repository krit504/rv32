# T4.3 — Recurring Toggle Attack

RTA is the author's group's prior work in TENDRA and the Write Hammer draft (local papers listed in T4.2). It alternates between two fixed targets; the LFSR varies each dwell time within the registry range. Direct stores use two geometry-derived cache lines. Paper stores sweep two arrays each larger than the D$, causing fills and dirty write-backs.

While inspecting the map, I found that a BSS-only program left `.data` empty, so `link.ld` put `.bss.target` next to `.text` instead of on a new page. A live initialized `data_page_anchor` now forces `.data` to 0x1000 and target BSS starts at 0x1010; stack begins at 0x3c000. This is a source fix, with no RTL or linker change.

The broad C5 mutant in `tests/attack_program.py` timed out for direct RTA because it also broke stack stores. New `tests/attack_mutant_control.py` applies a deliberately broken D$ to a temporary RTL copy, dropping stores only below the stack. It requires a completed **nonzero HALT**, so timeout is not accepted. Both RTA forms returned 127 on that broken core.

Acceptance commands:

```sh
scripts/run.sh -- .venv/bin/python tests/attack_program.py --kind RTA
scripts/run.sh -- .venv/bin/python tests/attack_mutant_control.py --kind RTA
scripts/run.sh -- .venv/bin/python analysis/attack_runner.py --case rta_direct_s1 --case rta_paper_s1
scripts/check_locks.sh
```

Native and RV32I caches off/on HALT 0, C5 mutant rejected, scoped mutant self-check HALT 127, and exact golden replay passes. Direct measured 2,007,370 cycles (PMR(all) 64.2312391); paper measured 1,971,492 cycles (PMR(all) 1.4883597). The generated wear files and source-hash sidecars are in `work/attack_run/`. Both PMRs are below benign `crc32`'s 127.937; this is a T4.7 acceptance conflict, not a reason to alter the source attack.
