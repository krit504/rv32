# T1.6 Random lockstep generator

- **Goal:** hazard-dense random programs (RAW gaps 1 to 3, load-use, taken and not-taken branches, `jal`, `jalr`, sub-word ops); compare final registers and memory against the reference model (Spike if available); at least 1000 programs per run, seeds logged. Accept: 0 mismatches; a seeded known bug (a mutant) is caught.
- **Done:**
  - `tests/random_gen.py`: seed to program. Forward-only control flow (always terminates), aligned accesses inside a 2 KiB data window based at `x31`, `x30` reserved as the jalr scratch, 70% of memory accesses in a hot 256-byte region (about 21% of loads read a word an earlier store wrote), source registers biased to the last three destinations. `pc_free` mode keeps pc-dependent values out of registers.
  - `tb/tb_random.sv`, `tests/random_lockstep.py`: one compiled testbench per configuration, one `vvp` run per program, comparing `x1..x29` and all 512 window words with `tests/refmodel.py`. A timeout or missing dump is a failure.
  - `tests/random_spike_check.py`: checks the model itself against Spike (200 programs, `pc_free`).
  - `tests/random_control.py`: five known-bad cores must fail, the unmodified core must pass. `make random`, and `random` is part of `make test`.
- **Results (seeds 1..1000, each line is one run):** caches off 1000/1000; no-forwarding 1000/1000; caches on LAT 1, 3, 10 each 1000/1000; also 500/500 caches on with no forwarding and 500/500 `pc_free`. Spike vs model 200/200. Control: H1 0/200 pass, H3 14/200, H5 10/200, S2 112/200, C4 57/200 (caches on LAT 3); unmodified 200/200.
- **Problems:**
  1. First Spike cross-check: 46 of 200 programs differed. The recurring value `0x1020` is Spike's boot ROM leaving the device-tree pointer in `a1` (x11) and clobbering `t0` (x5), while the RTL and model start with all registers 0, so programs that read a register before writing it saw different initial state. Not a model bug: the Spike build now zeroes x1..x29 first. After that 200/200 agree. The injected-bug controls prove the check is not vacuous: a model whose `lb` zero-extends fails 6 of 100, whose `sra` is logical fails 8 of 100, whose `blt` is unsigned fails 28 of 100.
  2. The first generator had a median of only 20 written window words out of 512, so most loads read zeros. Added the hot region (70% of accesses within 256 bytes) before the headline runs.
  3. The first suspiciously fast run (60 programs in 0.36 s) was checked by breaking the core rather than trusting it: four known-bad cores failed within the first 200 programs.
- **Deviations:** none. Changed locked file: `tests/run_mutants.py` (CHG-008).
- **Limits:** results are compared at HALT, not per instruction (the spec asks for final registers and memory). The generator never produces misaligned accesses or backwards branches by construction (KI-004).
