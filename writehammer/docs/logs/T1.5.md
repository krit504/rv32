# T1.5 riscv-arch-test target

- **Goal:** `riscv-arch-test` for the supported RV32I subset: signature dump and compare; exclude fence, ecall, ebreak, misalignment and CSR tests; documented include/exclude list. Accept: every included test passes; the pass list is in `docs/`.
- **Done:**
  - `tests/arch_test.py`: builds each `rv32i_m/I` test twice from the same source (tests/arch/model_spike and model_rtl headers, same `RVMODEL_HALT` instruction count so every symbol address matches, which the script verifies), runs the Spike build for the reference signature (`--isa=rv32i --priv=m`, `+signature`), runs the RTL build in `tb/tb_arch.sv` and compares the signature words exactly. The reference is Spike, never the RTL.
  - RTL: `RESET_PC` parameter on `pc` and the top (images linked at Spike's 0x80000000 sit at word 0 because the memories ignore high address bits) and a `dbg_widx`/`dbg_word` read port into the data memory (works with caches on or off).
  - Memories are sized per image: next power of two of the word count, at least 256 KiB (`jal-01` is 1.76 MB).
  - `docs/ARCH_TESTS.md` (subset and exclusions), `docs/ARCH_TESTS_RESULTS.md` (generated pass list), `make arch-test`, `tests/arch_mutant_check.py` (`make test-arch-control`).
- **Subset:** 37 of 39 tests. Excluded: `fence-01` (fence), `misalign1-jalr-01` (misaligned jump target). This suite version has no ecall/ebreak/CSR tests under `rv32i_m/I`.
- **Results:** `make arch-test`: 37/37 with caches off, 37/37 with caches on at LAT 1, 37/37 at LAT 10 (`docs/ARCH_TESTS_RESULTS.md`). Control: a core whose `lb` zero-extends fails `lb-align-01` and still passes `lbu-align-01`; a core whose `sb` byte enable is stuck fails `sb-align-01` (`make test-arch-control`).
- **Problems:**
  1. **Vacuous pass (the important one).** The first version reported tests passing, and a mutant with a broken `lb` also passed. Root cause: the test bodies are inside `#ifdef TEST_CASE_n`, which the official flow defines from the `def TEST_CASE_n=True` text inside `RVTEST_CASE(...)`. I never defined them, so no test code was assembled and both signatures were just the `0xdeadbeef` canary fill. Found because the signature printed as almost all `deadbeef` and the bad-`lb` mutant survived. Fix: define every `TEST_CASE_n` the source declares (and fail if it declares none). Regression guards in `arch_test.py`: the Spike signature must contain mostly non-canary words, and `arch_mutant_check.py` must see bad cores fail. The earlier "4/4 passed" results are void.
  2. `jal-01` timed out on the RTL. Root cause (log line `$readmemh: Too many words in the file for the requested range`): the test exercises jump offsets up to +-1 MiB and its image is 1.76 MB, larger than the 256 KiB memories. Fix: size the memories to the image. Not an RTL fault.
  3. Spike cannot map RAM over address 0 (its boot ROM is at 0x1000), hence the `RESET_PC` approach instead of linking at 0.
- **Deviations:** the run takes about 61 minutes (KI-009), so it is not in `make test`; the full-latency matrix (LAT 1, 5, 20, random) is T2.6.
