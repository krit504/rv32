# T1.1 Sub-word loads and stores

- **Goal:** `lb, lbu, lh, lhu, sb, sh`: decoder changes by `funct3`, byte-enable stores, load extender. Word path unchanged. Accept: lint clean, existing tests pass.
- **Done:**
  - `main_decoder` needed no change: it is opcode-only, so the new loads decode as `lw` (RegWrite, ResultSrc=01) and the new stores as `sw`. The width comes from `funct3`.
  - `funct3` is carried `d_e_reg` (already had `funct3E`) to a new `funct3M` field in `e_m_reg` (Q-003: required, otherwise Memory cannot tell `lb` from `lw`).
  - Store lane logic in the Memory stage (`rv32_top_pipelined.sv`): `sb` replicates the low byte across the word and enables lane `addr[1:0]`; `sh` replicates the low half and enables the half selected by `addr[1]`; `sw` enables all four. `StoreBEM` and `StoreDataM` feed `dmem` and `dcache`.
  - Load extender between the memory word (`ReadRawM`) and `m_w_reg` (`ReadDataM`): shift right by `8*addr[1:0]`, then sign- or zero-extend by `funct3`; `lw` bypasses the shift.
  - Byte enables added to `dmem`, `dcache` (store hit merges the enabled lanes) and `backing_mem` (the write merges the enabled lanes). The instruction-side `backing_mem` ties `be` to 0.
  - `dmem` zero-initializes (DEC-007).
- **Files changed:** `rtl/rv32_top_pipelined.sv`, `rtl/e_m_reg.sv`, `rtl/dmem.sv`, `rtl/dcache.sv`, `rtl/backing_mem.sv`.
- **Results:** `make lint`: 0 warnings. `make test`: every pre-existing test unchanged (21/21 x5, 25/25 x10, cache integration 36/36).
- **Problems:** retargeting mutant C5 after the D$ store-hit line changed (CHG-001): the harness reported `PATCH_FAILED` rather than silently passing.
- **Deviations:** none. Misalignment is unsupported (KI-004).
