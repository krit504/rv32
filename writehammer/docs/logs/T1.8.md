# T1.8 Benign workload set

- **Goal:** at least 4 Embench-IoT kernels that build for rv32i bare metal (log which and why any are skipped), `memcpy` and `memset` with buffers larger than the cache, and a store-heavy loop; each self-checks. Accept: all run correctly and appear in the baseline table.
- **Done:** `sw/embench/` (board hooks and builder; support code compiled unmodified), `sw/workloads/` (`memcpy_big`, `memset_big`, `storeloop`), `tests/workloads.py` (locked registry: calibration set and held-out set), `tests/workload_test.py`, the baseline table rows.
- **Embench survey (caches off, Verilator, 19 kernels):** all 19 build for rv32i and pass their built-in `verify_benchmark` (exit 0): aha-mont64 14.5 M cycles, crc32 6.8 M, depthconv 68 M, edn 102 M, huffbench 3.2 M, matmult-int 36 M, md5sum 3.1 M, nettle-aes 5.0 M, nettle-sha256 4.9 M, nsichneu 3.9 M, picojpeg 4.4 M, qrduino 6.5 M, sglib-combined 4.0 M, slre 3.4 M, statemate 3.3 M, tarfind 7.3 M, ud 8.8 M, wikisort 1.8 M, xgboost 4.3 M. Nothing is skipped for failing to build or check; edn, depthconv and matmult-int are excluded from the held-out set only for run time (DEC-008).
- **Held-out set (DEC-008, fixed before any detector exists):** crc32, md5sum, nettle-sha256, nettle-aes, huffbench, wikisort, sglib-combined, qrduino (Embench) plus memcpy_big, memset_big (16 KiB buffers, above the largest 8 KiB D$ of the study) and storeloop (32 sweeps of a 16 KiB array).
- **Oracles:** each Embench kernel's own `verify_benchmark` and each in-repo program's error count, **and** all of them compiled natively with the host gcc and run (the measurement hooks are no-ops under `-DNATIVE`): every one exits 0 natively, so the self-check logic is sound on a different compiler and ISA.
- **Results:** `tests/workload_test.py` 14/14: 11 workloads x (native + caches off + caches on at LAT 1 and 10) all exit 0; controls: H1 fails 11 of 11 workloads, H3 fails 5 of 11, C4 (caches on) fails 9 of 11. All 11 appear in `docs/baseline.md` with cycles, instructions, CPI and stall breakdown.
- **Problems:**
  1. A race in the Verilator runner: parallel workers built and overwrote the same cached binary while another ran it (`Text file busy`). Fix: exclusive file lock around the build and an atomic rename.
  2. The in-repo workloads needed a host-buildable path for the native oracle: `sw/mmio.h` gained a `NATIVE` branch (no-op hooks).
- **Deviations:** none.
